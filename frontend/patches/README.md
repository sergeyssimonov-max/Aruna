# Локальное исправление picomatch

Патчи для **2.3.2** и **4.0.7** закрывают воспроизведенный путь
[GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf):
повторяемый extglob с неограниченным внутренним повторением порождает регулярное
выражение с катастрофическим перебором. Примеры: `+(*a)` и `*(*)b`.

Исправление Aruna проверяет уже сформированное тело выражения в общем парсере,
до добавления внешнего `+` или `*`. Опасная конструкция вызывает `SyntaxError`
с кодом `ERR_PICOMATCH_UNSAFE_EXTGLOB`. Она не превращается молча в литерал.
Настройка `maxExtglobRecursion: false` эту защиту не отключает.

Это локальное ограничение: повторяемые extglob с неограниченными вложенными
выражениями больше не поддерживаются, включая некоторые допустимые, но
потенциально опасные сочетания. Обычные glob, конечные повторяемые выражения,
экранированные символы и классы символов сохраняются. Некорректные сочетания
`+(\*)` и `+(\+)` с `unescape: true` теперь явно отклоняются вместо прежнего
результата «ничего не совпало». Произвольные пользовательские регулярные
выражения и все прочие возможные классы ReDoS безопасными не объявляются.

Обе версии сохраняют исходные номера, зависимости и тексты лицензий. pnpm
записывает хеши патчей в `pnpm-lock.yaml` и применяет их при обычной установке:

```sh
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend exec vitest run tests/picomatch-security.test.ts
```

Тесты проверяют реальные цепочки Vite и WDIO, все активные установленные копии,
точные проверенные хеши патчей и исполняемых файлов вместе с package.json,
API компиляции, вложенные формы, режимы парсера, обычные пути и ограниченный
по времени процесс с исходным воспроизведением зависания. Неизвестная версия,
дополнительная непроверенная копия или измененный код приводят к отказу.
Остальные тесты проверяют сборку, детерминированность описи и пороги
Safari 16 / Safari 13.

GitHub отозвал бюллетень 18.11.2026. Aruna сохраняет оба патча и девять
проверок установленных копий. [Запись об отзыве](https://github.com/advisories/GHSA-fc5q-39xc-vjpf).

Команды `audit` и `audit:strict` сначала запускают весь файл
`tests/picomatch-security.test.ts`. Ошибка проверки или отсутствие тестов
останавливает скрипт до обращения к реестру. После успешной проверки скрипт
запускает штатный `pnpm audit` в каталоге `frontend` с политикой из
`pnpm-workspace.yaml`. В ней остаются два временных исключения для `glob`
и `minimatch` в инструментах тестирования окна.

```sh
pnpm --dir frontend run audit:strict
```

Строгий режим передает код завершения pnpm. В обычном режиме сетевой аудит
ограничен 30 секундами, и при таймауте скрипт явно сообщает, что аудит
не выполнен. `tests/audit-runner.test.ts` проверяет порядок вызовов,
рабочий каталог, политику, переданную pnpm, и обработку ошибок в обоих режимах.

Когда появится поддерживаемый исправленный выпуск, проверить его изменения,
выдержку, оба пути зависимостей и регрессионные тесты. После перехода на него
удалить соответствующие локальные патчи и записи `patchedDependencies`.
