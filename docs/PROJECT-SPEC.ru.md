   9.4. Фиксация версий зависимостей
      - Пакетный менеджер – только pnpm 11.22.0. npm запрещен как менеджер проекта: никаких npm install, update, ci; package-lock.json и npm-shrinkwrap.json в репозитории быть не должно; разовые запуски пакетов – через `pnpm dlx`, не npx. Запрет касается управления проектом, а не машины: npm остается частью Node-инсталляции.
      9.4.1. Lock-файлы
         - В Git фиксируются frontend/pnpm-lock.yaml, корневой pnpm-lock.yaml и src-tauri/Cargo.lock.
         - Поле `"packageManager": "pnpm@11.22.0"` в package.json удерживает версию менеджера через corepack.
         - Защита цепочки поставок pnpm 11 действует по умолчанию и не отключается: карантин новых версий (1440 минут, распространяется на транзитивные зависимости), запрет экзотических источников, контроль install-скриптов.
         - Решения по install-скриптам записаны явно в frontend/pnpm-workspace.yaml: edgedriver, esbuild и geckodriver – false. Незаполненные решения дают ошибку установки; esbuild работает без своего postinstall, потому что платформенный бинарник приходит отдельным пакетом через optionalDependencies.
      9.4.2. Почему это важно именно здесь
         - Платформа заморожена на macOS 13, и экосистема постепенно перестает ее поддерживать. Неконтролируемое обновление молча притащит версию, которая эту ОС уже не держит – именно так из стека выпал Playwright.
      9.4.3. Правило обновления
         - Обновление пина внутри патч-линии допускается при трех условиях сразу: релиз-ноты прочитаны, версии не меньше семи дней, есть причина (затрагивающий проект баг, безопасность) либо идет плановая ревизия перед новым этапом. После обновления – полный набор 9.12.
         - Транзитивные зависимости, которые Cargo или pnpm выбрали не самыми свежими, вручную не поднимаются: у Cargo выбор ограничен полем rust-version, и ручное вмешательство делает заявленный MSRV ложным.

   9.6. Требования к E2E-тестам
      9.6.1. Механика прогона (все пункты обязательны)
         - WebdriverIO с сервисом `@wdio/tauri-service`, в конфигурации указан `driverProvider: 'embedded'`: WebDriver-сервер работает внутри приложения, внешний драйвер не нужен.
         - Rust-плагины wdio регистрируются в Builder под `#[cfg(feature = "e2e")]`; для сборки без фичи объявлены пустые заглушки, чтобы цепочка Builder оставалась единой.
         - Разрешения `wdio-webdriver:default` и `wdio:default` лежат в src-tauri/capabilities-e2e/e2e.json – вне каталога, который сканирует build.rs. Иначе обычная сборка падает на неизвестных разрешениях. Файл встраивается через `include_str!` и регистрируется в setup вызовом `add_capability` под тем же cfg; трейт `tauri::Manager` импортируется тоже под cfg.
         - Фронтенд-половина `@wdio/tauri-plugin` импортируется в src/main.ts под условием `import.meta.env.VITE_E2E`. Без нее недоступен `core.invoke`. В обычной сборке переменная не задана, и импорт выбрасывается при сборке.
         - В tauri.conf.json включен `app.withGlobalTauri: true`.
         - Заголовок документа в index.html совпадает с заголовком окна, иначе сервис не находит окно.
         - При сборке с фичей `e2e` не регистрируется tauri-plugin-log.
         - Приложение собирается командой `cargo tauri build --debug --no-bundle --features e2e` с переменной `VITE_E2E=1`. Обычный `cargo build` не годится: он выставляет `cfg(dev)`, и окно грузит devUrl вместо собранного фронтенда – DOM оказывается пустым.
      9.6.2. Почему именно так
         - Приложение живет в системном WKWebView, и только прогон внутри приложения проверяет тот движок, в котором работает пользователь.
         - Альтернативы непригодны: у macOS нет WebDriver для WKWebView, внешний tauri-driver поддерживает лишь Windows и Linux, Playwright с 1.58 не поддерживает WebKit на macOS 13.
      9.6.3. Что проверяют сценарии
         - Приложение запускается, основной экран открывается, ключевые элементы видны, пользовательские сценарии работают, взаимодействие с окном работает.
         - Бекенд достижим: обращение через `browser.tauri.execute` возвращает ожидаемый результат. Текущий сценарий проверяет тип `core.invoke` и вызывает `plugin:app|version`, сверяя ответ с версией из манифеста.
      9.6.4. Критерий успеха
         - Сценарии проходят в реальном отладочном приложении на macOS 13, код возврата 0; в выводе репортера значится движок webkit на macos – это системный WKWebView.
         - Известный шум сервиса `@wdio/tauri-service` 1.3.0, не влияющий на результат и не устранимый настройками: диагностика об отсутствии tauri-driver (при embedded он не нужен) и сообщение об очистке моков в afterSession. Оба – дефекты сервиса, кандидаты в баг-репорт.
      9.6.5. Запрет для релиза
         - Оба E2E-плагина объявлены optional и включаются только фичей `e2e`, фронтенд-половина отсекается отсутствием VITE_E2E. Релизная сборка физически не содержит этого кода – гарантия механическая, а не дисциплинарная.
         - Проверка: состав зависимостей release-профиля.

   9.20. Журнал отклонений реальной сборки
      - Каркас: `pnpm init` вместо шаблона create-vite порождает конфликт полей packageManager и devEngines и не дает структуры проекта. Решение – шаблон svelte-ts с последующим приведением версий к пинам.
      - Пины: `pnpm add -E` не переписывает диапазоны у пакетов, уже присутствующих в манифесте. Семь версий из шаблона пришлось проставить вручную.
      - Настройки pnpm: поле «pnpm» в package.json в одиннадцатой линии не читается, настройки живут в pnpm-workspace.yaml. Автогенерированная заготовка этого файла содержит плейсхолдеры и требует заполнения.
      - esbuild: удалению не подлежит – его тянут сервис и плагин wdio, загрузчик конфигов и сам Vite. Платформенный бинарник приходит через optionalDependencies, поэтому блокировка postinstall безвредна.
      - Vitest: в jsdom-окружении Svelte 5 резолвится в серверную сборку; лечится `resolve.conditions: ['browser']`. Опция `hot` у vite-plugin-svelte 7 отсутствует.
      - Покрытие: в `include` попадают бинарные ассеты и css, если не сузить маску до кода.
      - Tauri: имя крейта из шаблона – app; переименование затрагивает три места (имя пакета, имя lib, вызов в main.rs). BSD sed на macOS не поддерживает границы слова.
      - Разрешения: файл capability, ссылающийся на плагины под фичей, ломает сборку без фичи – build.rs проверяет разрешения на этапе компиляции.
      - Логирование: два глобальных логгера в одном процессе несовместимы; при фиче e2e plugin-log не регистрируется.
      - Запуск приложения: `cargo build` дает `cfg(dev)` и загрузку devUrl; для E2E нужна сборка через Tauri CLI.
      - Мост wdio: требует одновременно импорта фронтенд-плагина, withGlobalTauri и корректного контекста в тесте (в колбэк передается core, объекта app там нет).
      - Заголовок окна: сервис ищет окно по заголовку документа, а не по конфигурации.
      - nextest: пустой набор тестов – код возврата 4.
      - Метаданные: description, authors, license и repository в Cargo.toml, а также относительный путь в beforeDevCommand появились вне сессии развертывания; расхождения зафиксированы и приняты.
