# Правила разработки Aruna

Прочитайте этот файл перед правками. Он действует для Codex и других агентов.
Работайте из корня текущего checkout, не из домашнего каталога. Явные указания
владельца в текущем задании имеют приоритет; прежние журнальные записи описывают
историю и не заменяют текущее задание.

Контракты продукта: `docs/FRONTEND-CONTRACT.md`, `docs/XML-CONTRACT.md`,
`docs/PDF-ACCEPTANCE.md`, `docs/FONTS.md`. Порядок проверок и выпуска:
`docs/TESTING.md` и действующие требования `docs/PROJECT-SPEC.ru.md`, особенно
разделы 6.2 и 6.8. Расхождение этих правил с действующей спецификацией считается
дефектом документации; исторические описания прежних версий не переписывайте.

## Продукт и платформа

- Один Rust workspace: `cli` / `aruna` – ядро и консоль; `src-tauri` /
  `aruna-desktop` – приложение с окном; `frontend` – Svelte 5, TypeScript и Vite.
  React и SvelteKit в проекте нет.
- Целевая платформа – macOS 13 Ventura на Apple Silicon. Обновление ОС невозможно.
  Сохраняйте floor `safari16` для окна WKWebView и `safari13` для экспортируемой
  описи. Зависимость, требующая более новой платформы, не подходит.
- Релиз – universal `Aruna.app` и DMG из `aruna-desktop`. `pnpm build` в корне
  запускает `scripts/build-release.sh`: Xcode 15.2 (15C500b), SDK 14.2, Node из
  `.node-version`, оба таргета Apple Darwin, переназначение путей для
  воспроизводимости. Внешние `RUSTFLAGS` и `CARGO_ENCODED_RUSTFLAGS` запрещены.
  `cli/build_app.sh` не является путем выпуска.
- Идентификатор приложения – `com.sergeyssimonov.aruna`; Cargo-бинарник –
  `aruna-desktop`. Версии обоих Cargo-пакетов и их записей в `Cargo.lock` совпадают.
  Подпись ad hoc задается в Tauri-конфигурации, не отдельным `codesign` после сборки.
- Node нужен только для разработки и сборки. Экспорт корпуса работает автономно.
  Файлы `cli/src/generated/` не редактируйте вручную: меняйте исходники в
  `frontend` и выполняйте `pnpm --dir frontend build:inventory`, затем проверяйте
  актуальность и детерминированность артефактов.

## Инструменты и зависимости

- Источники версий: `.node-version`, `rust-toolchain.toml` и `packageManager` в
  корневом `package.json`. Используйте закрепленные версии, не `latest` или
  подвижный канал Rust. Версию Rust не дублируйте полем `rust-version`.
- Менеджер проекта – только pnpm. Установка: `pnpm install --frozen-lockfile` и
  `pnpm --dir frontend install --frozen-lockfile`. Не используйте npm/npx для
  зависимостей проекта; разовые инструменты запускайте через `pnpm dlx`.
- Сохраняйте оба `pnpm-lock.yaml` и единый корневой `Cargo.lock`. В командах
  Cargo, которые разрешают зависимости, обязателен `--locked`. Обновление
  зависимостей – отдельная явная операция, после нее проверки снова идут с ним.
- Новые версии фиксируйте точно. Для обновления нужны причина, прочитанные
  release notes, проверка поддержки платформы и выдержка не менее семи дней,
  если владелец явно не разрешил исключение. Не делайте массовых обновлений
  «на всякий случай». Транзитивы выбирает резолвер: не переписывайте их версии
  вручную в lock-файлах и не обходите объявленные диапазоны без обоснования.
- Rust edition 2021, `#![forbid(unsafe_code)]` в собственных крейтах.
  `unwrap` и `expect` запрещены в коде приложения, кроме точки входа.
  Типизированные ошибки – через thiserror.

## Границы безопасности

- Изменения `tauri.conf.json`, capabilities и манифестов объясняйте явно.
  Разрешения окна – ровно `core:default` и `dialog:allow-open`, пока новый вызов
  из окна не обосновывает новое разрешение. Плагины только для Rust-стороны
  не получают разрешений окна. Для открытия файлов и ссылок используется opener,
  плагин shell не подключается.
- Геометрия окна меняется вместе: `resizable: false`, `center: true` и `main`
  в denylist плагина window-state. Сохранение размера не должно вернуть скрытые
  кнопки или окно за краем экрана.
- E2E-плагины остаются optional под фичей `e2e`, их разрешения – в
  `capabilities-e2e`, с регистрацией в рантайме. В релизе нет ни фичи `e2e`,
  ни `VITE_E2E`. В процессе только один логгер: tauri-plugin-log не регистрируется
  при `e2e`, где логгер устанавливает WebdriverIO.
- Соблюдайте контракты сохранности корпуса и PDF. Не принимайте изменившиеся
  снимки автоматически: обычные проверки запускаются с `INSTA_UPDATE=no`.
  Осознанное обновление снимков делается отдельно, с объяснением изменений.

## Правки и проверки

Правки Svelte выполняет Codex или агент с явно ограниченной областью работы.
Специальный плагин Claude Code не требуется. Проверки Svelte, типов, линтера и
компонентов обязательны независимо от способа написания кода.

Перед коммитом выполните из корня:

```sh
pnpm --dir frontend check
pnpm --dir frontend lint
pnpm --dir frontend format:check
pnpm --dir frontend test:unit
pnpm --dir frontend run audit
cargo fmt --all --check
cargo clippy --locked --workspace --all-targets --all-features -- -D warnings
INSTA_UPDATE=no cargo nextest run --locked --workspace --no-tests=pass
cargo deny check licenses bans sources
```

У nextest намеренно нет `--all-features`: `e2e` исключает тест, проверяющий
релизную конфигурацию. При изолированной правке одного Rust-крейта допустима
проверка соответствующего пакета через `-p`; изменение toolchain, lock-файла
или общего контракта требует обоих пакетов.

`audit` ограничен 30 секундами; отказ внешнего сервиса означает невыполненную
проверку, которую нужно назвать в отчете. Перед выпуском обязателен
`pnpm --dir frontend run audit:strict` без этого обхода. Не отключайте тесты,
линтеры, аудит или пороги, чтобы сделать результат зеленым. Ограничения среды,
включая отказы loopback, фиксируйте отдельно; не скрывайте их пропусками и
автоматическими повторами тестов.

Используйте явные пути в `git add`, не `git add -A` на весь репозиторий.
Разделяйте коммиты по областям: фронтенд и оболочка, ядро, документация.
Русские тексты: среднее тире, буква е вместо ё, «рублей» полностью, «ИТ».

## Приемка выпуска

Успешная компиляция не заменяет приемку. Перед выпуском пройдите полный набор
из спецификации: строгие аудиты (`cargo audit`, `cargo deny check`,
`pnpm --dir frontend run audit:strict`), `cargo machete`, покрытие обоих
контуров, тяжелые тесты настоящего корпуса, WebdriverIO внутри приложения,
PDF-заслон, воспроизводимость universal-сборки и путь читателя из DMG.
E2E-сборка запускается через `pnpm --dir frontend test:e2e`: локальный
закрепленный CLI выполняет `VITE_E2E=1 tauri build --debug --no-bundle --features e2e -- --locked`.
Глобальный `cargo-tauri` для нее не используется; релизная сборка –
`pnpm build --locked`, без этих E2E-переключателей.

Для выпуска 3.1.1 и следующих сравнивайте SHA-256 двух universal DMG из чистых
сборок одного коммита и скачанного образа CI. Tauri собирает и подписывает
приложение. Штатный упаковщик берет время коммита и проверяет приложение
в готовом образе. Для сборки из `git archive` задайте `SOURCE_DATE_EPOCH`
по `git show -s --format=%ct <коммит>` исходного репозитория.

Опорные теги и опубликованные артефакты не двигайте и не заменяйте новым
содержимым под прежним номером. Новая версия получает собственный номер.
Записывайте реальные команды, результаты и непроверенные условия. Не называйте
выпуск принятым, пока обязательные проверки не выполнены.
